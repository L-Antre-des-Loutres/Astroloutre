# Skin 3D sur la page joueur — plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** OAPI stocke la texture brute dans `players.skin`, et la page joueur Minecraft d'Astroloutre l'affiche en 3D avec skinview3d à partir d'une texture embarquée au build.

**Architecture:** Côté OAPI, `skin_service` envoie la texture ré-encodée au lieu du corps rendu, et `skin_hash` passe en `v2:` pour tout régénérer. Côté site, une fonction de build télécharge et valide la texture (PNG 64×64 ou 64×32) en `data:` URL ; un composant Astro rend un `<canvas>` piloté par skinview3d chargé via `import()` dynamique, avec repli sur l'image mc-heads.

**Tech Stack:** Rust (OAPI, `image` 0.25, mockito) ; Astro 5 + TypeScript, `skinview3d@3.4.2`, `node --test` (Node 24, types TS retirés nativement).

**Spec:** `docs/superpowers/specs/2026-10-25-skin-3d-design.md` (dépôt Astroloutre)
